# Tetris DevSecOps Platform on Amazon EKS

**Author / maintainer: Roudayna Kouka**

A secure, cloud-native three-tier platform: a **React** front end, a **Node.js** leaderboard API and an encrypted **Amazon RDS for MySQL** database, deployed on **Amazon EKS** with a full **DevSecOps** pipeline and **GitOps** delivery.

## What is in the repo

| Path | Content |
|---|---|
| `frontend/` | React Tetris, multi-stage Dockerfile (build -> unprivileged nginx), sends scores to the API |
| `backend/` | Node.js/Express API (`/api/scores`, `/healthz`, `/readyz`, `/metrics`), input validation, parameterised SQL, unit tests |
| `EKS-TF/` | Terraform: private subnets + NAT, EKS (encrypted secrets, control-plane logs), RDS MySQL (encrypted, TLS enforced, Multi-AZ option, managed password), ECR (immutable tags, scan on push), KMS key, IAM |
| `Jenkins-Server-TF/` | Terraform for the Jenkins/SonarQube EC2 server and base VPC |
| `charts/tetris/` | Helm chart: Deployments, Services, Ingress, HPA, PDB, NetworkPolicies, ExternalSecret, ServiceMonitor, PrometheusRule, Grafana dashboard |
| `argocd/` | Argo CD Applications: app, External Secrets Operator, kube-prometheus-stack (Prometheus, Alertmanager, Grafana) |
| `Jenkins-Pipeline-Code/` | `Jenkinsfile-EKS-Terraform` (infra) and `Jenkinsfile-Platform` (CI for the app) |
| `docker-compose.yml` | Run everything locally |

## Security measures

- **Network:** worker nodes and database in private subnets; RDS reachable only from the EKS node security group; NetworkPolicies on the pods.
- **Data:** RDS storage, ECR and Kubernetes Secrets encrypted with a customer-managed KMS key (rotation on); TLS required by MySQL; DB password generated by RDS and kept in AWS Secrets Manager, synced into the cluster by External Secrets (never stored in Git or Terraform code).
- **Containers:** non-root, read-only root filesystem, all Linux capabilities dropped, seccomp default profile, multi-stage images without build tools.
- **Pipeline:** SonarQube quality gate (blocking), OWASP Dependency-Check, Trivy on dependencies and secrets, Trivy on Terraform/Helm misconfigurations, Trivy on images (blocks fixable CRITICAL CVEs), immutable ECR tags.

## Deploy

1. **Prerequisites:** AWS account, S3 bucket for Terraform state (edit `bucket` in both `backend.tf`), an EC2 key pair (edit `Jenkins-Server-TF/variables.tfvars`).
2. **Jenkins server:** `cd Jenkins-Server-TF && terraform init && terraform apply -var-file=variables.tfvars`, then configure Jenkins (plugins: SonarQube Scanner, OWASP Dependency-Check, NodeJS, Pipeline: AWS Steps) and credentials `github`, `aws-key`.
3. **EKS, RDS, ECR:** run `Jenkinsfile-EKS-Terraform`, or `cd EKS-TF && terraform init && terraform apply -var-file=variables.tfvars`. Note the outputs `ecr_repository_urls`, `rds_endpoint`, `rds_secret_arn`.
4. **Cluster add-ons:** install Argo CD and the AWS Load Balancer Controller. Create the Grafana admin secret (command in `argocd/app-monitoring.yaml`).
5. **Configure the chart:** set `database.host`, `database.externalSecret.awsSecretArn` and the ECR repositories in `charts/tetris/values.yaml`; replace `YOUR-GITHUB-USER` in `argocd/*.yaml` and `Jenkinsfile-*`.
6. **GitOps:** `kubectl apply -f argocd/`. Argo CD installs monitoring, External Secrets and the app.
7. **CI:** create a Jenkins pipeline from `Jenkins-Pipeline-Code/Jenkinsfile-Platform`. Each run pushes images to ECR and commits the new tag, which Argo CD deploys.

## Monitoring and alerting

- The API exposes Prometheus metrics (request rate, latency histogram, scores submitted, Node.js runtime).
- `PrometheusRule` alerts: backend down, 5xx rate > 5 %, p95 latency > 1 s, crash-looping pods.
- Alertmanager groups and routes alerts (critical alerts repeat hourly). To receive notifications add a receiver in `argocd/app-monitoring.yaml`, for example Slack:
  ```yaml
  - name: default
    slack_configs:
      - channel: "#alerts"
        api_url_file: /etc/alertmanager/secrets/alertmanager-slack/url
  ```
  (and mount the secret with `alertmanager.alertmanagerSpec.secrets: [alertmanager-slack]`).
- Grafana dashboard "Tetris Platform" is provisioned automatically.

## Run locally

```bash
docker compose up --build   # game at http://localhost:8080, API at http://localhost:3000
```

## Cost warning

NAT gateway, EKS control plane, nodes and RDS are billed hourly. Run the `destroy` action of `Jenkinsfile-EKS-Terraform` when you finish.
